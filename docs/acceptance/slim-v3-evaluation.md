# 精简采访者 v3 与定点续写对照

- 目标：隔离提示词长度和两步选线的影响。原始用户文件留存在 docs/agents/。
- 新访谈采用精简常驻提示（1653 字符）及按需模块。已有访谈快照保持原版；自定义配置不自动覆盖。
- A：冻结 v2.4.14；B：精简单步；C：精简两步。C 共用 180 秒总预算，先校验简要诊断再生成正文；不存储模型内部推理。
- B/C 用同一确定性触发器，依据受访者文本保守加载模块；触发属于文本启发式，不等于已核实事实或阶段完成。无法从文本可靠判断的挑战与治理模块仅在明确意愿等条件下使用。
- 模块源文件中的外部案例摘要未重新核实，不视作新联网证据。

## 线上接口

POST /api/sessions 的 replay 参数：{sourceId, throughRound, variant: A|B|C}，mode 必须 human。只复制公开问答，所有组都移除原诊断，减少旧选线锚定；不读取或导出其他访客私有人设。源访谈模型必须等于网站当前模型。

然后调用原 POST /api/sessions/:id/step：每条续写仅生成一次采访者发言，成功后自动结束；不重跑受访者。原归属 Cookie、并发锁、每日配额与公开记录边界不变，无数据库结构迁移。

同一网关、同一网站模型；temperature、thinking、reasoning_effort 均不显式传入，沿用网站和网关默认。未宣称默认值已经核实。定点续写可以公开查看，诊断仍仅创建者可读。

## 运行与评审

从主项目执行 python -u scripts/run-slim-evaluation.py。仅使用网站公开 API 与进程内临时访客 Cookie，不读取 API 密钥。四个截断点 3/6/8/9，每组每点三次，共36条。最多三个独立请求同时运行，每个样本最多三次尝试，实际错误留档；失败重试可能带来选择偏差，报告中注明。

结果保存在被忽略的 data/diagnostics/slim-v3-evaluation/：results.json、逐样本 JSON、contexts.md、blind-review.md、unblind-key.json。盲评正文不包含诊断或组别，但风格差异仍可能泄露条件；单人事后评分不视作独立盲评。36条样本不足以证明长期效果。

正式产品先使用 B，C 作为实验条件；没有评审结论前不自动启用 C。

# 精简采访者 v3：线上对照结果

## 结论

36 个样本全部执行，34 个保存成功，2 个在最多三次尝试后失败。精简版出现了更好的成因/传承追问，但仍不稳定；没有证据证明两步选线稳定优于单步。当前网站新访谈使用 B（精简单步），C 保留为实验条件。这里是已知组别后的人工观察，不是独立盲评结果，不报告尚未完成的 6 分制盲评均分。

## 具体观察

- B-6-2：“这份信是怎么攒下来的？”抓住了信任的形成；B-3-2 邀请回忆办厂前的重要人物；B-8-2 追问为何不愿用自己的经历教育孩子。这些是局部改善证据。
- B-6-1 又追问客户如何变得被动，B-9-2 追问停线责任和处罚，说明精简提示并未稳定执行“收住操作细节”。B-8-2 使用“怕”，仍可能替受访者补入未核实的动机。
- C-3-1/2 回到成因，C-8-2/3 转向传承实践；但 C-8-1 仍追问谁拦住开工，C-9 三次全部围绕守规矩者是否吃亏。两步选线没有消除原先的选题倾向。
- C-3-3 的“凭什么觉得”把希望转成了待挑战的信念；C-9-3 一次给出多个负面情境并追加处置问题。两步组正文平均更长，也不能把多一次调用等同采访质量提高。
- A 第8轮后三次都围绕停线/开工；第9轮后仍多问压力和处置。A-8-2 虽触及老师傅的话如何影响决定，整体仍沿执行线。
- 诊断修复频繁：尤其 C 的12个成功样本中11个需要修复。该统计不说明具体是哪一字段出错；需保留初始无效诊断并进一步分析，不能臆断错误根因。
