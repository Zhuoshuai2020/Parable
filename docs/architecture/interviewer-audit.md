# 采访者 Agent 检查

本检查针对代码、原始 v2.4.12 配置与本地模拟 API 测试。原始候选配置保留原样，不代表访谈质量已通过。

## 结论

当前实现是带可编辑人设、方法文本与本场上下文的模型对话运行器。没有外部工具调度，也没有跨场长期记忆。保持这个 MVP 边界，不引入向量库或额外 agent 服务。

| 检查项 | 原状 | 本次处理及边界 |
| --- | --- | --- |
| 提问与回答记录 | 双方发言均已保存，但角色不突出，归档查看自动跳到底部 | 按“第几轮／采访者提问／受访者回答”展示，归档从头阅读；列表分别计数；新增完整问答 Markdown 导出 |
| 会话上下文 | 每次调用重传本场全部公开问答 | 保留该机制，暂停、刷新或服务重启后从 SQLite 读取；新会话不会自动读取旧会话 |
| 结构化工作状态 | 诊断已存储但未回传模型 | 采访者自己的历史发言带回其原始诊断，延续议题、证据、未决事项与下一步判断；不另起一次总结调用 |
| 工作状态来源 | 诊断是模型判断 | 记录包含对应消息 ID；不将其当成受访者确认或家族共识。缺诊断时状态为空，不补造 |
| 长期记忆 | 无 | 本次仍不实现跨场档案、记忆检索或自动合并成员观点 |
| 模拟隔离 | 独立人设、独立调用 | 只接收采访者公开正文，看不到采访者私有人设或诊断；同一模型不等于共享角色状态 |
| Skills | 文本方法注入 | 保持可编辑文本，未实现脚本、文件加载器、技能调度或网页搜索 |
| 配置 | 每场存初始快照 | 改动用于新场次；旧访谈继续使用原人设和方法。新增发言另记运行策略版本，区分后端规则变更 |
| 原始 bundle 运行配置 | `agent.json` 标记 `mode=mock`、`provider=none`，并包含旧工作台 endpoint 与 temperature | 当前只参考 `system.md` 和 `strategy.json` 及 skills 文本；不导入旧 mock 模式与旧接口，在线网关与模型由环境变量设置，temperature 使用供应商默认值。这不是整个旧工作台运行环境的移植 |
| 长访谈 | 不设上限地重传历史，有超限风险 | 增加 180000 字符本地上限，超过时明确拒绝继续生成并保留原记录；这不是供应商 token 上限，仍可能更早遇到供应商限制，不静默裁剪 |
| 输出截断 | 未检查供应商结束原因 | `finish_reason=length` 时拒绝将半条输出保存为完整发言，已有记录保留 |
| 产品能力承诺 | 实测出现“这段别记” | 运行策略明确所有提问回答均保存，不支持选择性免记录、撤回或删除；提示词约束不能保证模型永不违规，需继续行为验收 |
| 输出格式 | 正文与诊断分开，原文保留 | 保留；结构化诊断未全面做领域 schema 校验，不能作为自动法律结论或可信事实库 |
| 保密与访问 | 本地单用户，密钥仅环境变量 | 保持；SQLite 内容未做应用层加密，访谈内容会发送至配置网关，不是离线模型；不适合直接公开部署 |

## 最小记忆结构

1. 原始层：按顺序保存双方全文、角色、时间，AI 发言还保留原始响应与诊断。
2. 上下文层：每次生成都读取本场历史，按当前发言方映射 assistant/user；采访者自己的原始诊断回到自己的历史中。
3. 工作状态层：从最近一条有效采访者诊断派生，附来源消息 ID；随 JSON 导出，不混入给受访者看的 Markdown 正文。

三层都在现有会话数据中完成，无新增数据库或模型调用。这里的“记忆”不保证模型一定注意到每条历史信息，更不代表跨访谈身份识别或长期学习。

## 验证与剩余工作

自动测试覆盖问答顺序、导出、诊断回传及模拟隔离、重启后状态恢复、上下文超限和输出截断。本次没有为检查新增真实网关调用，真实多轮提问质量、长期不重复、反面挑战力度及提示词遵循仍待行为验收。
