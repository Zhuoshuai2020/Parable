# Git 管理约定

主仓库管理本地 Node.js 应用及 `website/` 网站源码、非敏感 Agent 配置、测试、脚本和必要文档。`sites/` 中的原独立工作目录继续忽略；供协作者使用的网站源码直接跟踪在 `website/`，不是子模块。Sites 导出 ZIP 是生成产物，不纳入本仓库。忽略文件仍留在本机，Git 不提供这些文件的备份。

## 日常开发

1. 开始前运行 `git status --short --branch`，确认当前分支和已有改动。
2. 较大任务从当前合适的基线创建 `codex/<任务名>` 分支。切换分支前确认已有工作归属，不覆盖其他任务。
3. 围绕一个可验收目标修改。源码、依赖配置及对应测试一起提交，保证每个代码提交能够运行；关联说明尽量随功能提交。
4. 运行 `npm test`、`node --check server.mjs`、`node --check public/app.js` 和 `git diff --check`。
5. 使用 `git add <文件路径>` 或 `git add -p` 暂存本次内容，再用 `git diff --cached` 核对，最后执行 `git commit`。
6. 推送、合并和发布由用户明确决定。本地提交后可用 `git log --oneline -5` 查看恢复点。

提交作者使用本仓库已核实的 GitHub 姓名和 noreply 邮箱，不修改全局身份配置。提交信息使用 `feat:`、`fix:`、`docs:`、`chore:` 等前缀，写明实际变化。

## 提交边界

- 提交：源码、测试、无密钥配置、导入与验证脚本、需求和架构说明。
- 验收记录与截图：只保留必要证据，提交前检查是否含真实访谈隐私、密钥、Cookie 或令牌。历史验收结论只代表当时版本。
- 不提交：`data/` 中的数据库、真实访谈与 Jobs 私有资料，环境配置、依赖、日志、缓存及生成 ZIP。
- 被忽略的本地数据需要另外备份；不要为了备份而强制加入公开源码仓库。
