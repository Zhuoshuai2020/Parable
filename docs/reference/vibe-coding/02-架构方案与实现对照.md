# Scala + React 架构方案与实现对照（v0.5）

后端采用 Scala 3、Cats Effect、HTTP API 和 PostgreSQL 关系型数据库；前端采用 TypeScript、React、Vite 与 Tailwind。业务代码按 `accounts`、`catalog`、`circulation` 组织，每个模块围绕自己的规则和数据提供完整能力。当前方案采用模块化单体：各模块在同一后端应用中运行，通过公开操作协作，保留清楚的数据所有权。

当前版本：v0.5，2026年10月28日。项目约束与[开发手册](01-软件系统开发规范.md)一致，具体路径和命令填写到[Scala + React AGENTS.md 模板](模板/Scala-React-AGENTS.md)。

建议以“声明式目标与页面、纯函数业务核心、IO 外部操作、强类型契约、按业务能力模块化”贯穿实现。前端从页面状态计算显示内容，后端将确定性规则与外部读写组织到各自位置，数据库按数据属主维护表和事务。

| 部分 | 默认架构 | 主要数据路径 |
| --- | --- | --- |
| 前端 | TypeScript + React + Vite；页面、hook、组件和业务调用器分工 | 操作 → 请求 → 响应校验 → 状态 → 界面 |
| 后端 | Scala 3 + Cats Effect；单应用内的业务服务分层 | 路由 → 类型化业务操作 → 所属表方法 |
| 数据库 | 一个 PostgreSQL 业务库；按领域归属组织表与有序迁移 | 服务数据访问 → 本地事务 → 关系表及约束 |

## 一、业务边界与整体目录

### 三个业务模块怎样分工

| 模块 | 负责的能力与数据 | 对外提供什么 |
| --- | --- | --- |
| `accounts` | 账号、角色、登录与会话；维护身份信息 | 识别有效会话、取得必要的身份或角色信息 |
| `catalog` | 书名、作者、ISBN、分类等书目元数据 | 查询和维护书目；提供稳定的 `bookId` |
| `circulation` | 馆藏副本、借阅记录、借阅额度与归还规则 | 查询可借副本、借阅、归还、查询个人借阅 |

`BookId` 标识一种书目，`CopyId` 标识某一本实际馆藏副本。一个书目可以对应多个副本，每个副本在同一时刻最多有一条有效借阅。副本状态与借阅记录由 `circulation` 一起维护，借出和归还涉及的变化进入同一数据库事务。

高内聚体现为相关规则、数据和改变原因集中在同一模块。调整借阅期限或归还规则时，主要变化应集中在 `circulation`。低耦合体现为调用者只需要理解公开输入和结果，`catalog` 修改内部书目字段时，借阅模块可以继续使用稳定的 `BookId` 与已约定的书目信息。

每个模块必须在 `docs/architecture/services.md` 登记业务职责、数据归属、公开操作、依赖方向、事务范围和验收入口。服务名称采用业务概念，评审时沿一次真实流程核对这些边界。

## 二、借阅接口的契约

`BorrowCopy` 表达“当前登录读者借阅指定馆藏副本”。前端提交副本标识，后端通过有效会话取得可信身份。两端都需要理解同一业务操作，网络请求与后端业务消息各自承载边界所需的信息。

| 项目 | 约定 |
| --- | --- |
| HTTP 入口 | `POST /api/circulation/borrow-copy`；项目注册该路径并保持调用器一致 |
| 会话 | 统一请求入口携带项目约定的会话凭证；后端校验后取得 `ReaderId` |
| 请求 JSON | `{ "copyId": "C001" }` |
| 成功 JSON | `{ "status": "borrowed", "loanId": "L001", "copyId": "C001" }` |
| 业务拒绝 JSON | `{ "status": "rejected", "reason": "copy_unavailable" }` 或 `loan_limit_reached` |
| HTTP 200 | 操作已得到确定的业务结果，响应为成功或业务拒绝联合类型 |
| HTTP 400 | 请求格式、字段或标识格式无效 |
| HTTP 401 | 会话缺失或无效 |
| HTTP 403 | 已识别身份缺少当前操作权限 |
| HTTP 5xx | 数据库或其他依赖故障，返回稳定的技术错误结构 |
| 重复提交 | 已借出的副本返回 `copy_unavailable`；需要返回第一次的同一结果时，另行约定请求标识与结果保存规则 |

技术错误响应统一采用 `{ "error": { "code": "invalid_request", "message": "副本标识格式无效" } }` 这样的结构。`code` 与 HTTP 400、401、403、5xx 分别对应项目定义的请求错误、身份错误、权限错误和服务错误；`message` 提供面向使用者的说明，内部堆栈留在后端日志。网络中断可能没有响应体，统一请求入口单独处理。

`copy_unavailable` 在当前契约中覆盖副本不存在、已借出或当前不可借。若产品需要区分这些原因，应扩展业务错误类型、响应编码和页面提示，并更新契约样例。HTTP 200 下的业务拒绝具有明确含义，页面可以提示选择其他副本或先归还已有借阅；技术错误进入单独的失败路径。

前端请求中出现的 `readerId` 字段应按请求校验规则处理，身份仍由后端会话解析结果提供。客户端可见的按钮状态用于交互提示，后端负责验证操作者对当前资源的权限。

## 三、一次借阅经过哪些步骤

1. `BookList` 展示书目与可借副本，用户选择 `CopyId` 后触发借阅动作。`apis/circulation/BorrowCopyAPI.ts` 生成约定请求，通用请求入口附加会话凭证。
2. `CirculationRoutes.scala` 解码 JSON，检查 `copyId` 的格式，验证会话，取得可信 `ReaderId`，构造 `BorrowCopyAPIMessage(readerId, copyId)`。
3. `BorrowCopyAPIMessage` 的 `plan(connection): IO[BorrowResult]` 组织权限与业务检查、事务执行和结果转换。依赖身份服务的外部查询应在进入数据库写事务之前完成；需要保持一致的本地规则在事务内依据当前数据核对。
4. `circulation` 的事务读取必要事实，检查借阅额度和副本状态，调用 `BookCopyTable` 改变副本状态，并调用 `LoanTable` 新增借阅记录。所有需要共同提交的读写使用同一事务上下文。
5. 事务提交后生成 `BorrowResult`。副本不可借或达到上限形成确定的业务拒绝；数据库执行失败触发回滚，并交给技术错误处理入口。
6. 路由把领域结果映射为响应 DTO，编码成 JSON。前端先校验响应，再更新页面状态和副本列表，显示借阅记录或明确的拒绝原因。

```text
BookList 页面
  → BorrowCopyAPI：{ copyId }
  → CirculationRoutes：JSON 校验 + 会话解析
  → BorrowCopyAPIMessage：可信 ReaderId + CopyId
  → 本地事务：BookCopyTable + LoanTable
  → BorrowResult → 响应 DTO → JSON
  → 响应校验 → BorrowState → 页面反馈
```

网络超时意味着当前调用尚未取得确定结果。页面应保留这一事实，并通过查询个人借阅等已有能力确认后端状态。重试方式依据该操作的重复执行约定确定。

## 四、后端层次与调用约束

| 位置 | 主要职责 | 允许的依赖 |
| --- | --- | --- |
| `objects/` | 业务标识、领域对象、有限状态、业务结果 | 所需基础类型及纯计算能力 |
| `objects/apiTypes/` | 请求和响应 DTO、编解码及转换 | 对应领域类型和协议编码能力 |
| `api/` | 一个公开操作的业务步骤，构造输入与 `plan` | 所属领域类型、表方法、已声明的外部契约 |
| `routes/` | 注册 HTTP 入口，解码、解析身份和编码响应 | 业务操作、DTO、通用 HTTP 与身份入口 |
| `tables/` | 所属表的参数绑定、查询、写入和记录映射 | 所属领域类型及数据库基础设施 |
| `utils/` | 当前模块复用的纯业务计算或辅助逻辑 | 该模块明确允许的依赖 |

`tables/<XXTable>/` 按表组织读写与初始化文件。`XXTable.scala` 负责查询和执行，`XXTableInitializer.scala` 负责初始化检查或接入统一迁移入口；表结构定义以 `backend/migrations/` 为权威来源。一个领域对象通常单独成文件；一个 API 文件围绕一个业务操作。主要步骤应能从 `plan` 看出，已有操作能够直接承载流程时，保持这一层次。多个返回字段组成明确的响应类型；无业务输入的操作可直接使用无参数入口。

`tables/` 默认由所属模块内部使用。其他模块通过公开业务操作取得所需结果。既有同进程项目保留公开 Table 方法时，必须在服务卡中登记调用方、数据属主、权限检查和事务责任；该兼容约定适用于同一部署单元。

模块依赖保持单向。出现 `catalog` 与 `circulation` 双向调用时，应检查书目事实、馆藏事实和流程协调的归属。共享类型仅包含边界需要的标识与交换信息，业务实体和内部数据库模型由各自模块维护。

### IO 与事务的责任

`IO[A]` 表达执行后产生 `A` 的效果计算；`map` 变换成功值，`flatMap` 或 `for` 连接依赖前一步结果的操作。业务层组织完整计算，运行时入口执行它。数据库、网络和文件访问集中在有明确资源生命周期的位置。

数据库事务负责相关写入的共同提交与回滚。`plan(connection)` 中的连接必须与事务执行器提供的上下文一致，表方法使用该上下文完成整个借阅操作。`IO` 的步骤组合需要配合实际事务实现，才能使副本状态和借阅记录保持一致。

事务内只包含维护当前业务事实所需的数据库操作和短时计算。远程身份查询、消息发送等网络操作具有独立的超时和失败行为，应安排在明确的事务边界之外，避免长期占用数据库连接。借阅成功后需要发送通知时，应先明确通知是否影响借阅结果，再确定其执行位置。

实际支持并发借阅的项目，应依据数据库能力选择条件更新、行锁或合适的唯一约束，检查操作结果并守住“同一副本最多一个有效借阅”的规则。额度检查也需要与当前读者的新增借阅共同满足业务一致性要求。针对推测性或极低概率情况增加锁、重试或分布式协调前，必须说明具体问题、概率依据、实现维护成本，并获得项目负责人明确同意。

## 五、强类型与数据转换

### Scala 业务类型

```scala
final case class BookId(value: String)
final case class CopyId(value: String)
final case class ReaderId(value: String)
final case class LoanId(value: String)

enum CopyStatus:
  case Available, Loaned

enum LoanStatus:
  case Active, Returned

enum BorrowError:
  case CopyUnavailable, LoanLimitReached

final case class Loan(
  id: LoanId,
  readerId: ReaderId,
  copyId: CopyId,
  status: LoanStatus
)

type BorrowResult = Either[BorrowError, Loan]
```

`ReaderId` 和 `CopyId` 具有不同类型，参数交换可以在编译阶段暴露。构造入口仍要检查格式，数据访问和权限流程继续检查真实记录与操作资格。领域类型使用不可变字段，内部集合也应符合项目的不可变约定。

业务操作的结果为 `IO[BorrowResult]`。`Right(loan)` 表达借阅成功，`Left(BorrowError.CopyUnavailable)` 表达正常完成后的业务拒绝，数据库连接失败进入 `IO` 的技术失败处理。查询副本可以使用 `IO[Option[BookCopy]]`：查询成功而缺少记录得到 `None`，查询执行失败走技术错误路径。

`Try[A]` 可用于捕获一次可能抛异常的同步转换，例如文本转整数。转换成功后仍需检查借阅天数范围等业务规则。每个类型只承担明确的结果含义，调用者据此安排分支。

### JSON、领域对象与数据库记录

| 表示层 | 例子 | 转换责任 |
| --- | --- | --- |
| 请求 JSON | `{ "copyId": "C001" }` | 路由检查对象结构、字段类型和允许的值 |
| 请求 DTO | `BorrowCopyRequest(copyId: String)` | 校验构造 `CopyId`，结合可信身份形成业务消息 |
| 领域输入 | `ReaderId`、`CopyId` | 业务操作检查权限、资格及当前状态 |
| 数据库记录 | `book_copies` 的列、`loans` 的列 | Table 显式映射字段、空值、存储状态和领域类型 |
| 领域结果 | `Either[BorrowError, Loan]` | 映射为公开的成功或业务拒绝 DTO |
| 响应 JSON | `status`、`loanId`、`copyId` 或 `reason` | 前端运行时校验后形成可信结果 |

数据库中的状态字符串需要映射成枚举，未知值进入可追查的错误处理。API 只输出契约声明的字段，数据库内部字段可以独立演进。简单场景可复用同一结构，字段含义或生命周期出现差异时建立显式转换。

### TypeScript 契约与页面状态

```typescript
type BorrowCopyResponse =
  | { status: "borrowed"; loanId: string; copyId: string }
  | {
      status: "rejected";
      reason: "copy_unavailable" | "loan_limit_reached";
    };

type BorrowState =
  | { status: "idle" }
  | { status: "submitting" }
  | { status: "completed"; result: BorrowCopyResponse }
  | { status: "failed"; message: string };
```

`BorrowCopyResponse` 对应网络契约，`BorrowState` 表达页面交互过程。`completed` 状态下继续处理成功与业务拒绝两个分支，`failed` 表达当前调用遇到的传输、解码或技术问题。增加状态后，应通过穷尽检查和代表性输入检查全部处理分支。

项目应开启 TypeScript 的 `strict`，在验收时运行真实类型检查命令。`response.json()` 的返回值先按 `unknown` 接收，交给统一解码函数检查 `status`、必需字段、字段类型和拒绝原因枚举；校验通过后返回 `BorrowCopyResponse`。类型断言只表达编译时判断，网络校验必须实际执行。禁止通过 `any` 或强制断言掩盖外部输入的类型问题。

运行时解码可以直接检查契约需要的字段，再构造合法结果。以下函数与前面的 `BorrowCopyResponse` 类型配合，解码错误进入技术失败路径；项目已有 Schema 校验工具时，可由工具承担同样的检查。

```typescript
function decodeBorrowCopyResponse(value: unknown): BorrowCopyResponse {
  if (typeof value !== "object" || value === null || !("status" in value)) {
    throw new Error("借阅响应缺少状态");
  }
  if (
    value.status === "borrowed" &&
    "loanId" in value && typeof value.loanId === "string" && value.loanId.length > 0 &&
    "copyId" in value && typeof value.copyId === "string" && value.copyId.length > 0
  ) {
    return { status: "borrowed", loanId: value.loanId, copyId: value.copyId };
  }
  if (
    value.status === "rejected" && "reason" in value &&
    (value.reason === "copy_unavailable" || value.reason === "loan_limit_reached")
  ) {
    return { status: "rejected", reason: value.reason };
  }
  throw new Error("借阅响应字段或状态无效");
}
```

`type CopyId = string` 只能提供名称，普通字符串别名仍然可以互换。需要隔离关键标识时，可使用带区分字段的对象或品牌类型，并把构造集中到校验入口；网络 DTO 继续保持约定的字符串字段，进入业务层时完成转换。

## 六、前端目录、状态与请求

`BookList/index.tsx` 组合搜索、书目列表、副本选择和结果提示。页面专用组件、Hook、类型与纯函数留在 `pages/BookList/`，跨页面稳定复用的基础组件进入 `components/ui/`。简单区域可以保持一个组件文件，复杂区域按实际职责建立目录。

`hooks/useBookList.ts` 协调加载、选择副本、提交和更新状态；`functions/` 保存筛选、排序等纯计算；`objects/` 保存页面专用结构。核心状态有明确归属，筛选结果和格式化文字由已有状态计算得到。

`apis/circulation/` 与后端 `services/circulation/api/` 保持可追踪的操作对应，`objects/circulation/` 保存相关接口类型与前端业务类型。通用发送、会话凭证、HTTP 技术错误处理集中在 `system/api/`。后端仅供内部使用的操作按调用需求配置入口。

API 调用可以统一采用 `new BorrowCopyAPI(...).send()`，也可以采用 `sendAPI(new BorrowCopyAPI(...))`。项目选择一种调用形式，并在 `AGENTS.md` 写清 API 名称、路径映射和响应解码入口。

共享 Store 保存跨页面使用的事实，对外提供快照读取、订阅和更新操作。页面持续显示当前值使用订阅，一次操作记录当时输入可以使用快照。Effect 连接网络、浏览器接口和订阅等外部过程，明确依赖及必要清理。列表页面应区分加载、空结果、就绪和失败，借阅动作另有提交反馈。

样式可统一采用 Tailwind，布局围绕页面业务区域组织。废弃脚手架文件按确认后的用途清理，源码、构建产物与验收记录分别进入约定目录。

## 七、数据库演进与独立部署

### 同一应用的数据库迁移

当前 `backend/migrations/` 由同一部署单元统一执行，迁移编号在整个应用内保持唯一、顺序明确。每个文件注明涉及的模块与数据属主，表结构、旧数据转换和约束由对应模块维护。已经在共享环境执行的迁移保留，后续变化追加新的迁移文件。

`BookCopyTable` 负责 `book_copies`，`LoanTable` 负责 `loans`，两者同属 `circulation`。迁移应定义副本标识、借阅标识、状态、关联和必要约束，并结合已有数据检查约束能否成立。表中的索引依据实际查询、过滤和排序路径确定。

同一应用数据库中的内部关系可使用外键。跨模块外键和查询依赖应登记到架构说明，以便在未来调整部署边界时一并处理。

### 具备独立部署需求时

独立发布节奏、明确的扩容差异或团队职责可以构成拆分理由。每次拆分应记录收益、网络调用成本、运行维护责任和验收条件。拆分后的目录可以采用：

```text
project/
  services/
    accounts/                      # 独立构建、配置、源码、迁移和测试
    catalog/                       # 独立构建、配置、源码、迁移和测试
    circulation/                   # 独立构建、配置、源码、迁移和测试
  contracts/                       # 服务间公开交换契约
  frontend/
  docs/architecture/
```

每个独立服务拥有自己的依赖清单、启动入口、配置示例、数据访问权限、迁移顺序和验收命令。服务之间通过公开网络契约协作。禁止导入其他服务的 `tables/`、私有领域实现或复用对方的 `Connection`，禁止直接读写对方业务表。共享数据库实例时，也应通过独立库或 schema 和权限明确数据归属。

`circulation` 内部继续以本地事务维护副本与借阅。账号和书目关联通过稳定标识表达，依赖事实按公开接口取得。独立服务分别执行自己的迁移；同一仓库中的目录位置与服务的发布、运行和数据边界应保持一致。

跨服务流程必须明确发起方、最终状态属主、部分完成时的反馈及失败处理责任。引入消息队列、补偿流程或其他协调机制前，应结合已经确认的业务场景说明成本和必要性。

## 八、项目评审与验收

- 每个模块能否说明业务能力、所属表、公开操作、依赖方向及修改原因？一次借阅规则变化是否主要留在 `circulation`？
- `system/` 与 `services/` 是否同级？页面、业务调用器、领域类型、表方法和迁移是否进入约定目录？
- 请求中的 `copyId` 在哪里校验？会话在哪里转换为可信 `ReaderId`？操作权限在哪里检查？
- `BorrowCopyAPIMessage` 是否返回明确的成功或业务拒绝？HTTP 请求错误与技术错误是否经过单独处理？
- 副本状态与借阅记录是否使用同一事务上下文？写入失败时是否共同回滚？实际并发场景是否守住业务不变量？
- 领域类型、DTO 和数据库记录之间的转换是否明确？未知状态、缺值和错误输入在哪里被处理？
- TypeScript 严格检查是否执行？网络响应是否经过实际校验？页面是否处理了加载、空数据、提交、成功、拒绝和技术失败？
- 迁移是否兼容已有数据并有明确执行顺序？构建、契约样例和关键业务流程是否留下真实验证结果？
- 独立部署的服务是否具有独立启动和迁移入口，跨服务依赖是否只经过公开契约？
