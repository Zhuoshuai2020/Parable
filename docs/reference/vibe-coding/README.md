# Vibe Coding 手册

当前版本：**v0.5**，更新日期：2026年10月28日。

从业务目标出发，用声明式描述目标和状态，用纯函数与不可变值组织计算，用强类型连接业务信息，再通过高内聚、低耦合的模块划分、明确的目录和验收安排完成软件开发。

## v0.5 的建议架构与要求

新项目建议使用以下组合，既有项目沿用已确定的技术栈，并将业务职责和依赖约束落实到现有结构。

| 部分 | 建议架构 |
| --- | --- |
| 前端 | TypeScript + React + Vite，按页面、状态、组件、纯函数和业务 API 分工；Tailwind 作为样式选择 |
| 后端 | Scala 3 + Cats Effect + HTTP API，以模块化单体组织逻辑业务服务 |
| 数据库 | PostgreSQL 单业务库，表按业务域分组，由所属服务的数据方法访问，采用有序迁移和本地事务 |

- 用声明式表达目标、输入输出和合法状态；业务计算采用纯函数与不可变值，外部操作通过明确的副作用边界执行，Scala 使用 `IO` 组织这些操作。
- 前端明确页面、状态、组件、纯计算和 API 请求的分工，覆盖异步交互和运行时数据校验。
- 后端明确路由、身份与权限、业务操作、领域类型、数据访问及外部操作边界。
- 数据库明确数据属主、字段与约束、查询需求、事务和迁移。
- 每个服务按高内聚、低耦合划分，登记业务能力、所属数据、不变量、公开契约、依赖和部署方式。
- 关键身份与状态进入类型系统，缺值、业务拒绝和技术失败分别表达；TypeScript 项目采用严格检查。
- 项目登记根目录及业务目录映射，约束跨目录依赖；源码、测试、迁移、配置、产物和文档分别归位。

课程中的逻辑微服务在同一应用内组织。独立部署方案需要明确实际收益和运行维护成本；数据访问通过所属服务契约，事务范围与部署边界保持一致。借书例子将副本状态和借阅记录放在 `circulation` 共同维护，书目归 `catalog`，身份归 `accounts`。

## 开始项目

1. 写清用户、问题、核心流程和完成标准。
2. 列出关键对象、不变量及服务卡。
3. 选择模板，填写真实目录、契约入口和检查命令。
4. 按可验收的小任务实现，检查实际数据流、类型与依赖边界。
5. 保存架构决定、迁移及验收结果。

## 网页生成与分享

在手册目录运行 `python3 网页/build.py`，从两份 Markdown 正文重新生成 `网页/index.html`。构建需要 Python 的 `mistune` 和 `beautifulsoup4`；可在独立虚拟环境中安装后运行。CSS 与 JavaScript 内嵌在网页中，正文可以离线阅读。

分享完整文件夹时，对方打开 `网页/index.html` 即可阅读。模板链接依赖 `模板/` 目录；课程来源链接依赖相邻的 `99_HTML笔记/` 目录；官方文档链接需要网络。单独分享手册时，正文和本地模板仍可阅读，课程原文需通过原课程资料查看。

`python3 网页/prepare_github_pages.py` 可生成发布准备目录和分享包。本次更新交付本地手册；发布准备目录、已有分享包和线上站点需要依据实际使用需求另行生成或发布。
