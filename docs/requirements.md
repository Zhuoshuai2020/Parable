# AI 预访谈 MVP

状态：已实现本地 MVP；Node.js 单应用、原生前端与 SQLite。API 网关和模型已选定，密钥待运行环境提供；真实模型兼容性及访谈质量待验收。

## 目标

让准备制定家族宪章的创始人完成一轮 AI 文字预访谈；让开发者通过独立模拟受访者测试采访者，并保留可回看的完整记录。

## 第一版范围

1. 前端典雅、正式、结构清晰。按用户反馈降低年轻化表达，采用深蓝、米白与少量金色，减少装饰，突出访谈内容和记录。
   - 统一暖灰页面、白卡片与白输入框；选中项采用淡金底、金色左边线和对勾。
   - 小反馈 180ms，首次页面进入 360ms、错开 70ms，使用先快后缓曲线；同一浏览器会话返回页面不重播。
   - 新生成回复按段落显现，单段 380ms、段间错开 320ms；历史内容直接展示。等待时使用慢呼吸圆点。尊重系统减少动态效果设置。
   - 模型名称与采访者参考版本仅在 Agent 设置展示；访谈页面不重复品牌标识。
2. 采访者是通过在线模型 API 运行的 agent，不包含主动网页搜索或查证工具。参考项目现有 interviewer-v2.4.12 人设和策略，允许用户继续修改人设与 skills。保留原始参考文件，不直接覆盖。
3. 支持真人回答和模拟受访者回答。模拟受访者是独立配置与独立模型调用，不与采访者共享私有人设；采访者只看到对话内容。未来可接入乔布斯模拟人物，第一版预留同一种接入方式。
4. 自动保存整场访谈：每条发言的角色、内容、时间、顺序，以及所用采访者和模拟受访者配置版本。刷新后可查看已保存记录，支持导出。
5. 记录明确展示采访者提问与受访者回答，按轮次组织，支持完整问答文本和 JSON 导出。采访者使用本场全部历史与自己的诊断状态；暂无跨场长期记忆。检查结论见 `docs/architecture/interviewer-audit.md`。

## 最小界面（初步方案）

- 访谈：创建会话，选择真人或模拟模式，开始、暂停或结束，阅读对话并回答。模拟模式可逐步运行或连续运行，需有轮数上限及停止入口。
- Agent 设置：编辑采访者人设与 skills；编辑或选择独立的模拟受访者。首版使用文本编辑，不建设技能市场或复杂编排器。
- 历史记录：查看整场访谈并导出。区分进行中、已结束及真人/模拟模式。

## 记录与配置边界

- 每场访谈保存配置快照，修改配置默认用于新访谈，避免旧记录无法复现配置来源。
- 发言生成成功后持久化；API 失败清楚显示，允许重试，不伪造发言或重复追加已成功的记录。
- 模拟资料与真人访谈明确标识。模拟人物不代表真人实际回答。
- 密钥仅由服务端持有，不写入前端、Git、导出记录或人设文件。

## 暂缓

语音、录音转写、律师正式访谈、AI 总结、多成员协作、家族共识分析、宪章生成、复杂权限与插件平台。

## 待确认的关键含义

- 已确认：“通过 API 联网”指调用在线模型，第一版不包含网页检索。
- 已选择网关 `https://llmapi.paratera.com/v1` 与模型 `DeepSeek-V4.1-Flash-1017`。全部通过服务端环境变量 `PARABLE_API_BASE`、`PARABLE_MODEL`、`PARABLE_API_KEY` 配置，不加载 .env 文件，密钥不写入文件或配置包。首版仅本机运行，采用兼容 Chat Completions 的接口格式。
- skills 采用可编辑的访谈方法文本；若需执行脚本或外部工具，另行定义范围。

## 验收

- 能完成一次真人文字访谈，结束后完整回看与导出。
- 能运行一次有明确停止条件的双 agent 模拟，清楚区分双方发言。
- 能修改采访者配置，新会话使用新配置，历史会话保留原配置快照。
- 刷新页面不会丢失已保存发言；API 失败可识别且不会形成虚构记录。
- 现有 v2.4.12 是待验证参考，完成接入不等于已通过访谈质量验收。
